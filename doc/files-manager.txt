*files-manager.txt*  本地可编辑 buffer 文件管理器（Neovim 0.12）

==============================================================================
入口                                                        *files-manager*

    :Files [目录]      打开目录；省略目录时打开当前文件的父目录。
    -                  普通文件中打开父目录，并定位当前文件。

也接管 nvim .、nvim <目录>、:edit <目录>。不修改 cwd，不依赖 Oil 或 shell。

目录中的快捷键：
    <CR>               打开文件 / 进入目录
    -                  返回父目录
    <C-v> / <C-x>      竖分屏 / 横分屏打开条目
    g.                 显示 / 隐藏隐藏文件
    gr                 重新扫描；有编辑时先确认是否放弃
    q                  返回上一个 buffer，未提交编辑可保留在隐藏 buffer
    g?                 本帮助
    :w                 预览操作，确认后执行；默认选择 Cancel

文件管理器是 acwrite buffer；当前配置的自动保存不会提交它。关闭 Neovim
前请主动保存或放弃编辑。会话中的目录 URI 重新读取磁盘，不持久化未提交计划。

==============================================================================
编辑语义                                                 *files-manager-edit*

每行实际文本类似：
    /000001 src/
    /000002 README.md

前缀是默认隐藏的身份 ID；图标是虚拟文本，不进入寄存器。不要手工修改 ID。
需要检查原始文本时可 :setlocal conceallevel=0。

    o notes.md         插入无 ID 行：创建空文件
    o docs/            以 / 结尾：创建目录
    o docs/guide.md    创建文件和缺失的父目录
    cw / 替换          保留 ID 改名：重命名；名称中含 / 时移动到子目录
    dd                 删除条目（提交后进入暂存区）
    yy p，修改副本名    原行仍在、同一 ID 有新的名称：复制
    调整行顺序          无文件操作
    u / <C-r>          撤销 / 重做尚未提交的文本编辑

空行忽略；前后空格是文件名的一部分。新条目的内容为空。
cc/S 会删除 ID，表示删除旧条目并创建新文件，不是保留内容的重命名！
批量替换请只改名称。确认清单中 RENAME 的实际标签为 MOVE。

一个 ID 的原位置消失且只剩一个目标时，表示移动；原位置消失但有多个目标
时有歧义，拒绝提交。复制已有目录包括其隐藏内容；符号链接不递归跟随。

刷新、切换隐藏文件或提交成功后会分配新 ID，并清空旧的 undo 历史。
旧寄存器里的 ID 将拒绝使用。跨目录 buffer 的剪切/粘贴尚未实现。
刷新前隐藏的文件不会因为不在 buffer 中而被删除。

==============================================================================
安全与恢复                                             *files-manager-safety*

每次非空提交显示完整操作清单，必须手动确认。:w! 不跳过确认或冲突检查。
正常路径下不覆盖已有目标；文件名交换与大小写重命名通过中间位置处理。

操作前检查磁盘快照及涉及的未保存文件 buffer。确认前后递归核对源条目。
重命名会更新已打开文件的 buffer 名称（包括目录后代）；删除会关闭对应的
未修改 buffer。涉及未提交的后代目录 buffer 时拒绝移动/删除。
不提供 LSP willRenameFiles/didRenameFiles 或自动修改引用。

删除和操作日志位于当前目录下：
    .nvim-files-trash/txn-XXXXXX/
        journal.json   原计划、步骤、状态、恢复信息
        source-N       暂存的删除条目或失败操作的源

暂存区永不显示为可编辑条目，不自动清理，也不是系统回收站。
可将 .nvim-files-trash/ 加入项目或全局 Git ignore；插件不修改 Git 配置。

    :FilesRestore      在当前目录选择一个已完成事务，恢复其删除条目
    :FilesClean        永久清理一个已完成事务及其中的暂存文件（另需确认）

恢复不会覆盖已存在的同名路径。失败/未完成事务不能自动清理或自动恢复。
进程崩溃后，检查 journal.json 的 pending、steps 和真实磁盘状态，手动搬回
source-N 等残留条目。不要只删除失败日志，以免连同剩余文件一起丢失。

执行失败会停止、尽可能按逆序回滚；回滚也可能失败。失败计划保留在 buffer
中并锁定编辑，查看报错中的日志路径，处理残留后用 gr 重新扫描。部分复制
失败时可能留下不完整目标，不会贸然删除这些内容。成功保存后的 u 不恢复
文件操作；被删除内容请用 FilesRestore 恢复。

限制：
- 只支持本地文件系统；首版不支持跨设备移动/嵌套挂载点、远程协议。
- 只接受当前目录内相对路径；拒绝 ..、绝对路径及符号链接父目录写入。
- 不支持在同一提交中向正在移动/删除的源目录内部写入。
- 不支持控制字符、换行、反斜线名称和特殊文件；出现时视图整体只读。
- Windows 符号链接复制未实现；Windows 实机行为仍需额外验证。
- 扫描和操作同步执行；单个递归源最多 10000 条目、深度小于 100。
- 指纹使用 inode/设备、大小、权限、mtime/ctime，不是文件内容哈希。
- 初次展示不递归扫描目录；删除/复制目录以确认前扫描到的内容为准。
- 多步操作不是原子事务；崩溃/断电和外部进程并发修改不能完全隔离。
  尤其检查目标存在与 rename 之间仍有竞争窗口；重要内容应另有备份。

开发                                                     *files-manager-dev*

    nvim --headless -u NONE -l tests/files/run.lua

模块位于 lua/plugins/files/，启动配置位于 plugin/90_plugins/14_files.lua。
使用 vim.uv，无外部 shell/第三方插件依赖。mini.icons 已加载时展示图标。
